# STM32 3D 打印耗材烘干控制器

> 2026-09-17前馈更新：已实测24°C室温下40°C/60°C保温输出28.9611%/53.5925%，当前F22=clip(11.99435×(目标−12.83620),0,850)，再按(目标−室温)/(目标−22)缩放。此前20.13/34.65及旧表为历史值，以本条和`outputs/feedforward_calibration_24c/REPORT.md`为准；旧版实测不代表新曲线验证。


这是一个基于 STM32F103C8T6 的 3D 打印耗材烘干控制器固件。系统读取箱内温湿度，监测风扇运行状态，通过 XY-MOS 控制 12V PTC 加热器，并使用旋转编码器和 SSD1306 OLED 完成参数设置与状态显示。

## 功能

- AHT20 与 BMP280 按 70% / 30% 融合为一个温度，用于 PID、LCD 和网关；湿度来自 AHT20，两路原始温度保留独立超温保护。
- SSD1306 实时显示温湿度、风扇状态、电机状态、运行时间和加热状态。
- SSD1306 初始化为180度旋转显示，以适配当前反装的屏幕。
- 依次设置温度阈值和湿度阈值，两项均可单独设为 `OFF`。
- 旋钮菜单 `ROOM TEMP CAL` 手动输入当前室温（−10～50°C，1°C 步进），该值参与保温前馈并保存、上报给网关。
- 温度、湿度均为 `OFF` 时进入只吹风模式，PTC 始终关闭。
- PB8 通过 TIM4_CH3 输出高电平有效的 10Hz 控制信号，驱动 XY-MOS。
- 板载 PC13 加热指示灯按实际加热占空比闪烁：占空比越高闪烁越快，稳态低占空比时闪烁间隔自动变长，占空比为 0 时熄灭。
- PA0 通过 TIM2_CH1 输出 20kHz PWM，PA2 保持低电平，驱动 DRV8870 正转；电机只在实际加热烘干时运行。
- 风扇停止、传感器失联或过温时立即关闭 PTC。
- W25Q Flash 保存温湿度目标、阈值启用状态及手动室温；旧记录默认室温 22°C。
- 传感器和 OLED 支持运行期间重新探测。
- 每秒通过 PB13/PB14/PB15 的 SPI2 半双工接口发送 64 字节 CRC 状态帧，并在同一周期接收 64 字节控制命令。
- ESP32-S 接入局域网后提供实时曲线、历史数据、CSV 下载以及启停和温湿度目标设置，电脑或手机无需安装客户端。
- ESP32-S 默认开启演示热点 `Temperature-Gateway`，密码为 `temperature`，访问地址为 `http://192.168.4.1`；配置局域网后热点仍保持开启，方便现场演示。
- PB15 与 ESP32 GPIO23 分时双向传输，四根线即可完成监控与控制；PA9、PA10 和 ESP32 GPIO17 均不使用。
- 远程启动采用 5 秒租约。ESP32 在远程任务运行时每秒续租，链路或 ESP32 失联后 STM32 自动停止该任务。

ESP32-S 接线、固件构建和网页使用步骤见 [ESP32 局域网监控与控制网关](esp32_gateway/README.md)。

## 控制规则

- 温度阈值启用时，反馈控制器持续调节 0～100% PTC 占空比；达到目标后由前馈、比例、积分、微分和降温补偿共同维持温度，不采用固定的目标加 0.30°C 停热门槛。
- 温度阈值关闭时，仍保留 70°C 安全控温上限和 75°C 锁存过温保护。
- 湿度阈值启用时，达到目标湿度后暂停加热，高于目标 2%RH 后允许恢复。
- 风扇信号在任务启动后有 6 秒建立时间；停止状态持续 500ms 会终止任务并关闭 PTC。
- 风扇恢复运行 200ms 后自动清除 `FAN ERR`，但任务不会自动重新启动。
- 传感器失联时每 2 秒尝试恢复 I2C2，故障期间禁止加热。
- 电机与PTC加热状态同步：`HEATING` 时正转，等待、保持、只吹风、停止或故障状态下停转。
- 网页或 HTTP API 发出的远程启动不会绕过上述风扇、传感器和过温联锁；条件不满足时 STM32 拒绝启动并返回原因。
- 远程控制的任务只有在持续收到 ESP32 心跳时保持运行；5 秒租约到期后 PTC 和电机关闭，任务停止。

## PID 温控算法

当前固件的控制器实现在 `Core/Inc/separation_pid.h`，名称虽然保留为 PID，但它是一个带趋势预测和安全限制的离散 PID 型控制器。控制器只在收到新的有效温度样本、目标改变或首次初始化时计算一次；主循环约每 2 ms 运行，温度采样约每 1 s，不能把主循环频率当作 PID 采样频率。加热器的 TIM4 PWM 载波为 10 Hz，两次 PID 计算之间保持上一次占空比。

### 1. 反馈量与误差

两路温度先融合，再作为 PID 的唯一反馈：

```text
T = round_away_from_zero(0.7 × T_AHT20 + 0.3 × T_BMP280)
e = target - T
```

`T` 以 0.01°C 保存，PID 计算时换算为 °C。两路原始温度仍分别用于有效性检查和独立过温保护；任一路失效时禁止加热，任一路达到 75°C 时锁存过温故障。温度关闭而湿度控制仍启用时，控制目标使用 70°C 安全上限。

### 2. 采样时间与斜率滤波

相邻有效传感器样本的实际时间差为 `dt`，由 STM32 tick 计算，而不是假定固定 1 s。重复样本只在目标改变时重算输出，不推进积分或微分；`dt < 0`、`dt > 5 s` 或时间戳异常会复位控制器并输出 0。

测量斜率和一阶低通滤波为：

```text
s = (T[k] - T[k-1]) / dt
v[k] = v[k-1] + dt/(1+dt) × (s - v[k-1])
```

其中 `v` 是滤波后的升降温速率，单位为 °C/s。微分只使用测量值变化，不直接对误差差分，所以目标阶跃不会产生虚假的微分冲击。

控制器还对上一次输出做 4 s 时间常数的滤波：

```text
H[k] = H[k-1] + dt/(4+dt) × (u[k-1] - H[k-1])
```

`H` 只是近期输出的记忆量，不是热量或热容的精确估计。

### 3. 满功率速率表与增益调度

系统使用 2026-09-16 满占空比试验得到的升温速率表 `R(T)`（单位 °C/s），在相邻节点之间线性插值；节点外保持首尾值：

| 温度节点 °C | 35.5 | 40.5 | 45.5 | 50.5 | 55.5 | 59.5 |
|---:|---:|---:|---:|---:|---:|---:|
| `R(T)` °C/s | 0.4533 | 0.4346 | 0.3619 | 0.2761 | 0.2058 | 0.1420 |

由速率表计算温度相关增益：

```text
g = clip(0.4346 / R(T), 0.8, 2.0)
```

温度越高、满功率升温越慢，`g` 越大，P、I、D 三项都会相应增强。它是经验增益调度，不代表已经完成全温区稳定性证明。

### 4. 趋势预测、P 项与 D 项

只对正在升温的趋势做短时预测：

```text
v+       = max(v, 0)
L        = 1.7 + 0.5 × clip(H, 0, 1000) / 1000   (s)
Tpred    = T + L × v+
ep       = target - Tpred
P        = Kp × g × ep
D        = -Kd × g × v+
```

预测时间 `L` 随近期输出在 1.7～2.2 s 之间变化。温度正在上升时，D 项提供制动；温度下降时 `v+ = 0`，D 项不产生负的额外制动，下降恢复由 P、已保留的积分和下一节的有限补偿共同完成。

固件启动默认参数为 `Kp=200`、`Ki=2`、`Kd=180`、积分分离阈值 `2°C`，输出单位为千分比（`1000 = 100%`）。ESP32 的 `/api/pid` 可以在运行时提交 Kp、Ki、Kd，范围分别为 0～500、0～50、0～1000；参数只保存在 RAM，STM32 重启后恢复默认值。

### 5. 条件积分与抗饱和

积分是慢速保温修正，不负责冷启动阶段的主要升温。只有同时满足以下条件时才更新：

1. `abs(e) <= separation`，默认误差不超过 2°C；
2. 下降扰动冻结计时已结束；
3. 当前欠温但预测值已经到温时，不继续累加正积分。

候选积分为：

```text
alpha = (e > 0 and v > 0) ? clip(1 - v/0.30, 0.25, 1) : 1
Icandidate = clip(I + alpha × Ki × g × e × dt, -250, 250)
```

控制器再用候选积分计算临时输出。只有临时输出位于 0～1000，或积分变化能够把已饱和的输出往回拉时，才接受候选值；否则保留旧积分。这是条件积分抗饱和，没有独立的反算跟踪项。

温度下降扰动满足 `e > 0.4°C` 且原始斜率低于 −0.10°C/s 或滤波斜率低于 −0.05°C/s 时，积分冻结 12 s；目标改变时至少冻结 5 s。调低目标会立即丢弃正向积分修正，保留负向修正，避免旧目标的热量记忆继续推高输出。

### 6. 接近目标时的下降补偿

当温度接近目标（`−0.20°C < e <= 2°C`）且滤波斜率为负时，控制器增加一个有上限的补偿：

```text
B = clip(-v × (1000 - F) / R(T), 0, 100)
```

`B` 最多为 100‰，即额外 10 个百分点。温差较大时不启用该项，避免开盖等大扰动同时触发过强的补偿；大幅掉温主要由 P 项和已经存在的积分修正恢复。

### 7. 合成输出与独立安全门

当前主线的 PID 合成式为：

```text
F22 = clip(11.99435 × (target - 12.83620), 0, 850)
F = clip(F22 × max(target - ambient, 0)/(target - 22), 0, 850)
u = clip(F + P + I + D + B, 0, 1000)
```

室温前馈已参与实际控制；ROOM TEMP CAL必须填写真实箱外室温。2026-09-17在24°C环境校准40/60°C，随后实测50→52→54°C。Kp=200在50→52°C的±0.2°C稳态时间为13秒（原160为16秒），超调0.16°C（原0.13°C）；首次升至50°C仍曾超调0.46°C。见outputs/temperature_optimization/REPORT.md。

PID 输出还要经过外层安全状态机：未启动、风扇启动等待、风扇故障、传感器失效、75°C 锁存过温、湿度达标或只吹风模式都会强制关闭 PTC。温控阶段电机保持运行，即使本次 PID 输出暂时为零；停止、故障和湿度暂停时电机关闭。

## 上位机监控与控制

ESP32 网页每秒更新温湿度曲线，同时显示任务、加热器、电机、风扇、输出、目标值、故障和最近一次命令结果。网页可执行启动、停止、温湿度目标设置和故障清除。HTTP 客户端可通过 `GET /api/status` 和 `GET/POST /api/control` 接入后续自动化 PID 调整测试。

控制请求可以选择是否把目标写入 W25Q Flash。自动化调参时建议保持 `persist=false`，只在需要断电保存最终参数时写入，避免高频试验造成不必要的 Flash 擦写。完整接线、请求格式和返回状态见 [ESP32 局域网监控与控制网关](esp32_gateway/README.md)。

## 编码器操作

1. 空闲主页面短按，进入温度设置。
2. 旋转选择 `OFF` 或 30~70°C，短按进入湿度设置。
3. 旋转选择 `OFF` 或 10~80%RH，短按进入 `ROOM TEMP CAL` 室温校准。
4. 旋转选择当前箱外室温（−10～50°C，默认 22°C），短按进入启动确认。
5. 旋转选择 `START` 或 `SAVE ONLY`，短按应用并保存全部设置。
6. 运行中长按 1 秒停止任务；设置页面长按返回上一步，温度页面长按取消本次编辑。

室温是手动输入值，不会自动跟随环境变化，也不改变箱内传感器示值。当前主线用它缩放保温前馈；环境变化后应重新输入。未连接可用 W25Q 时设置仅在本次通电期间生效。

## 构建

需要 CMake 3.30 或更高版本，以及 Arm GNU Toolchain，其中 `arm-none-eabi-gcc`、`arm-none-eabi-g++` 和 `arm-none-eabi-objcopy` 应位于 `PATH` 中。

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel
```

构建完成后会生成：

- `build/demo_led.elf`
- `build/demo_led.hex`
- `build/demo_led.bin`

## 安全提示

本项目控制 12V / 100W 大电流 PTC。PTC、风扇和电机电流不得经过开发板，功率回路应使用合适线径、保险丝和星形接地。首次调试时先断开 PTC 和电机，确认 PB8、PA0、PA2 在空闲和故障状态为低电平，再分别连接功率负载。远程控制仅进入同一套安全状态机，不替代独立保险丝、温控器或其他硬件断热措施。
